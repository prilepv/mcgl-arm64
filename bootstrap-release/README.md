# Minecraft Galaxy ARM64 — Bootstrap 1.6.6

Неофициальный нативный ARM64-порт Minecraft Galaxy для Mac с Apple Silicon.

## Главное отличие этой сборки

Архив **не содержит Minecraft.jar, mcgl.jar, игровых ресурсов, музыки, текстур
или других файлов клиента Minecraft Galaxy**. При первом запуске приложение
получает официальный список файлов, скачивает клиент напрямую с зеркал MCGL,
проверяет MD5 каждого файла и только затем устанавливает ARM64-компоненты порта.

Первоначальная загрузка составляет примерно 232 МБ и может занять несколько
минут. До полного завершения не закрывайте лаунчер.

## Изменения 1.6.6 — «Новая орбита»

- Новый интерфейс с боковой навигацией «Играть», «Настройки», «Журнал».
- Собственные тёмные сине-фиолетовые фон и иконка, заметная кнопка запуска,
  единая строка состояния на всех экранах.
- Одна кнопка запуска и остановки: её подпись меняется по состоянию игры.
  Во время подготовки и завершения повторное нажатие недоступно.
  Enter запускает готовый клиент, но не останавливает уже работающий.
- Убраны дублирующие заголовки, у всех галочек светлые читаемые подписи.
- В настройках — отдельные блоки памяти и графики; журнал получил отступы
  для читаемого отображения начала строк.
- Переключение разделов: Command+1, Command+2, Command+3.
- Обновление с 1.6.5 доступно через существующую проверку GitHub Releases:
  скачайте DMG, закройте игру и лаунчер, замените приложение в «Программах».
- Сохранены каталог клиента, логин и настройки. Версия игровых патчей остаётся
  1.6.5: новый интерфейс не вызывает повторную установку патчей и не меняет
  выбранную пользователем сортировку прозрачности.
- Фон статический; фоновой анимации и постоянного цикла перерисовки нет.

## Изменения 1.6.5 — новый лаунчер и прозрачность

- Параметры вынесены на отдельную вкладку; журнал больше не занимает экран входа.
- Начальная память Java (Xms) и максимальная память (Xmx) выбираются независимо.
  Лаунчер не позволяет задать начальное значение выше максимального.
- При запуске проверяется последний релиз `prilepv/mcgl-arm64` на GitHub. Новый
  DMG загружается в «Загрузки» и открывается для ручной замены приложения;
  запущенная программа не перезаписывает саму себя.
- Добавлены собственные фон и иконка неофициального ARM64-порта.
- Штатная сортировка прозрачных блоков теперь включена по умолчанию. При первом
  обновлении существующего профиля с 1.6.4 значение `alphaSort:false` один раз
  меняется на `true`; затем пользователь снова может менять его вручную.
- Быстрый QuadSort, VBO/VAO, освещение, анимации и качество изображения сохранены.
- Диагностический журнал графики по умолчанию выключен и включается отдельно.

## Изменения 1.6.4 — обновление освещения без лишних загрузок

Карта освещения 16×16 теперь не отправляется повторно в OpenGL, если её
пиксели побайтово совпадают с предыдущими. Расчёт света, мерцание, яркость,
частота тиков и анимаций остаются прежними; графические настройки не снижены.
Привязки и параметры текстур выполняются и при пропуске передачи пикселей.

Обновление этой отдельной карты больше не очищает кеш анимаций terrain/items.
Обычные загрузки, замены и удаления текстур по-прежнему сбрасывают кеши.
Новый контекст OpenGL и другой texture id не наследуют старое содержимое.
Новые патчи устанавливаются только при совпадении проверенных методов клиента.

При включённой «Диагностике графики» добавлена строка `[MCGL Lightmap]`:
`checks`, `uploads`, `skipped`, `invalidations` и среднее/максимальное время
вызова передачи пикселей. Это время вызова на CPU, включая ожидание драйвера,
а не отдельное GPU-время. Настоящий выигрыш FPS проверяется в той же сцене.
Технический возврат прежнего пути для сравнения: `-Dmcgl.lightmap.cache=false`.
Java, GC, лимит FPS и нативный оконный механизм в этой версии не менялись.

## Изменения 1.6.3 — диагностика плавности

Новая сборка добавляет измерение отдельных кадров, не изменяя картинку,
алгоритмы рендера, Java/GC, симуляцию или выбранный лимит FPS.
Включите «Диагностику графики» перед запуском игры.

- `[MCGL FramePacing]`: примерно раз в 5 секунд — среднее, максимум,
  p50/p95/p99 времени кадра и p95 отдельно для кадров с игровым тиком и без.
  Процентили показаны верхними границами с шагом 0.1 мс; `>100` — переполнение
  диапазона, а не точное значение. Интервал — между концами Display.update,
  не время физического показа на мониторе.
- `[MCGL SlowFrame]`: до трёх самых длинных кадров >16.67 мс за окно,
  с временем рендера, тика, анимаций, пересборок, Display.update, ожидания
  ограничителя FPS и swap. `endEpochMs` указывает время события, а не
  отложенной записи отчёта. `other` — не охваченный основными фазами остаток.
- Анимации вложены в тик, чанки — в рендер, cap/swap — в update. Их нельзя
  складывать повторно. Это wall time, включая ожидания, не чистое CPU/GPU время.
  `crossedPhase/overlapFrames` отмечают неоднозначность вложенных обновлений.
  `diagnosticLogs` учитывает старые отчёты Display/Phases, иногда вложенные
  в другие интервалы; это не полный расход всех диагностических механизмов.
- Два заранее выделенных окна статистики и три записи медленных кадров:
  новая диагностика не создаёт объекты на каждом кадре. Один daemon-поток
  спит до отчёта. Если вывод заблокирован, игровой поток продолжает работу,
  окно измерения продлевается; очередь и память не растут без ограничения.

Для следующего замера постойте перед лавой 30 секунд без движения камеры,
потом 30 секунд посмотрите в лёгкую сторону. Не меняйте одновременно
разрешение, дальность и лимит FPS. Эта сборка собирает доказательства для
следующей оптимизации, а не обещает заранее устранить найденные задержки.
Техническое отключение только нового счётчика: `-Dmcgl.frame.profile=false`.
Снятие галочки диагностики отключает также новые счётчики и их поток.

Цель компиляции лаунчера явно закреплена на macOS 14.0, как уже было указано
в Info.plist. Ранее фактический минимум исполняемого файла был macOS 15.0.
Это исправление совместимости не объясняет само по себе отказ на macOS Tahoe.

## Передача друзьям и первый запуск

Передавайте исходный ZIP релиза целиком. Получатель распаковывает его штатной
«Утилитой архивирования» macOS и переносит целое приложение в «Программы».
Не пересылайте внутренний исполняемый файл или разобранное содержимое .app.
Нужны Apple Silicon (включая M1), macOS 14+ и интернет для первого скачивания
клиента. ARM64 Java 8 уже внутри: системная Java, JAVA_HOME, Homebrew и Rosetta
для запуска этой сборки не нужны.

Сборка имеет локальную ad-hoc подпись, но не Developer ID и не нотариализацию
Apple. На другом Mac защита macOS может потребовать подтверждения. Если
проверен источник файла и macOS сообщает о непроверенном разработчике,
используйте разрешение именно для этого приложения в «Системные настройки →
Конфиденциальность и безопасность». Не отключайте Gatekeeper целиком.
Предупреждение о вредоносном коде нельзя считать обычным запросом разрешения.

Общее сообщение «Не удаётся открыть программу» не устанавливает причину:
нужны точный ZIP/версия и сведения с компьютера получателя. В частности,
переустановка Java не чинит испорченную упаковку или отказ проверки подписи.
Для распространения без ручного разрешения требуется Developer ID, корректная
подпись вложенного исполняемого кода и нотариализация; ZIP/DMG сам по себе
не заменяет эти шаги.

Справка Apple: [безопасное открытие приложений](https://support.apple.com/102445),
[нотариализация](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution).

## Изменения 1.6.2 — смена текстур в VBO

При включённой VBO-отрисовке чанков поддержаны переключения обычных 2D-текстур
внутри графического списка. Раньше такой список целиком оставался на старом
рендере. Теперь подходящая геометрия может использовать VBO/VAO, сохраняя
порядок команд, выбор активной текстуры и последующие обновления её содержимого.

Остальные неизвестные команды и не-2D цели текстур сохраняют прежний fallback.
Пустые списки, вложенные списки и COMPILE_AND_EXECUTE не переводятся на новый
путь. Геометрия, освещение, сортировка прозрачности, текстуры, дальность,
частицы, анимации, Java/GC и оконные исправления не изменены.

Новые поля `[MCGL VBO]`: `textureCompiles` — сколько списков со сменой текстуры
успешно переведено на VBO за окно отчёта, `textureBinds` — сколько записанных
переключений воспроизведено. Это не количество блоков и не время GPU.

Новая поддержка работает внутри имеющейся галочки VBO. Снятие галочки
выключает VBO/VAO целиком. Для точного технического A/B только этого изменения
сохранён параметр `-Dmcgl.chunk.textureBindings=false`: он возвращает прежний
fallback при смене текстуры, сохраняя остальные оптимизации. Обычный запуск
не требует параметров. Прирост FPS зависит от сцены и требует замера;
одна лишь частота `glBindTexture` не доказывает причину просадки.

## Изменения 1.6.1 — диагностика спавна

Рендер и качество изображения остаются как в 1.6.0. Эта сборка предназначена
для выбора следующей оптимизации, а не обещает новый прирост FPS.

При включённой «Диагностике графики» добавлены:

- `[MCGL Chunks]`: число завершённых пересборок геометрии, суммарное время,
  среднее и максимальное время за окно около пяти секунд. Это часть времени
  рендера, её нельзя ещё раз прибавлять к `[MCGL Phases]`.
- `[MCGL VBO fallback]`: первая причина, по которой компиляция геометрии
  осталась на прежнем рендере, и число таких случаев: конкретная GL-команда,
  активные входные массивы, формат/размер, бюджет либо ошибка загрузки VBO.

Число `chunk updates` в игре — пересборки, а не число сетевых загрузок чанков.
Оно не равно `display lists` в пятисекундном журнале: одна пересборка может
создавать несколько графических списков. Новые счётчики не отменяют, не
объединяют и не откладывают обновления блоков/света.

Эксперимент с объединением соседних native-списков прошёл проверки картинки,
но не дал ускорения на тестовом Mac и в эту сборку не включён.

Для следующего замера оставьте включёнными VBO и диагностику, постойте на
одном месте 20 секунд с тяжёлым направлением взгляда, затем 20 секунд с лёгким.
Профиль и мир не требуют сброса. Пароль в диагностику не записывается.

## Изменения 1.6.0

- Квадратичная сортировка прозрачных четырёхугольников заменена стабильной
  сортировкой индексов с однократным переносом вершин. Результат, включая
  равные расстояния и особые значения координат, совпадает с исходным порядком.
  Уже упорядоченная геометрия не копируется. Этот патч действует и без VBO;
  исходный алгоритм сохранён для неподдержанных размеров входа. Рабочие массивы
  повторно используются, ограничены примерно 9 МиБ на вызывающий поток.
- В режиме VBO формат вершин и настройки массивов сохраняются в APPLE VAO:
  вместо повторного задания указателей и атрибутов при каждом рисовании
  выбирается готовая настройка. Требуется поддержка драйвером OpenGL 2.1;
  при её отсутствии или ошибке создания VAO остаётся обычный VBO-путь.
- Полностью нативная группа display lists больше не разбивается на отдельные
  вызовы. Порядок смешанных групп native/VBO остаётся прежним.
- Поиск геометрии по ID не создаёт Integer на каждом обращении. Удаление
  одного списка больше не просматривает весь кеш чанков. Диагностика реже
  проверяет часы на пути одиночных списков.
- Состояние клиента OpenGL сохраняется и восстанавливается, включая чужой VAO,
  указатели на память Java и переходы между VAO и обычным VBO. VAO удаляется
  вместе со своим буфером; старые имена не используются после смены контекста.
- Галочка VBO и выбранные настройки сохраняются. VAO работает внутри этого
  режима автоматически. Для отключения VBO/VAO сними галочку;
  для сравнения именно с 1.5.0 используй сохранённую предыдущую сборку.
- Геометрия, текстуры, прозрачность, дальность, анимации, параметры Java/GC и
  исправления окон не изменены. Лимит дополнительных вершинных буферов —
  прежние 256 МиБ; служебные объекты VAO требуют небольшого дополнительного
  объёма памяти драйвера. Конкретный прирост FPS зависит от сцены.

В диагностике `[MCGL VBO]` появились `vaos`, `vaoDraws` и `nativeBatches`:
число живых VAO, рисований через них и целиком сохранённых нативных групп.
В начале сессии печатается `VAO=true/false`. Число `nativeCalls`, как прежде,
считает элементы списков, не обязательно отдельные обращения к драйверу.
Строка `[MCGL QuadSort]` показывает число сортировок, обработанных
четырёхугольников и уже упорядоченных наборов. Для диагностического сравнения
сохранён JVM-параметр `-Dmcgl.quad.sort=false`; обычный запуск его не требует.
Патчер проверяет отпечаток исходного метода сортировки перед установкой.

## Изменения 1.5.0

- Добавлена галочка «VBO-отрисовка чанков (экспериментально)». По умолчанию
  выключена; выбор сохраняется и действует при следующем запуске игры.
- Собранная геометрия чанков рисуется из VBO без повторного исполнения
  старого списка вершин. Координаты, текстуры, свет, порядок проходов и
  сортировка прозрачных поверхностей не изменяются. Отсечение невидимых
  чанков остаётся штатным.
- Исходные display lists сохраняются: необычные GL-команды, неподдержанные
  состояния массивов или ошибка загрузки буфера включают прежний рендер
  для соответствующего списка. Дополнительные VBO ограничены 256 МиБ;
  это не настройка Java heap и не резерв всей GPU-памяти.
- Буферы освобождаются при замене/удалении списков. При замене OpenGL-контекста
  старые идентификаторы не используются. С включённой диагностикой строки
  `[MCGL VBO]` показывают объём буферов, число отрисовок и возвратов к спискам.
- Патч входит в установку официальных обновлений. Три метода, определяющие
  формат вершин и проходы чанка, проверяются до трансформации. Если MCGL
  изменит именно этот код, потребуется адаптация патча; неизвестный формат
  не устанавливается поверх рабочего клиента.

Для сравнения запусти одну сцену с галочкой и без неё, сохранив одинаковые
размер окна, направление взгляда, дальность и лимит FPS. При артефактах или
ухудшении скорости сними галочку и перезапусти игру. Ускорение синтетического
рисования не является гарантией прироста FPS на сервере.

## Изменения 1.4.1

- Для неизменившегося кадра анимации пропускается не только передача в GPU,
  но и копирование пикселей в промежуточный буфер. Обновление эффекта и
  переключение текстуры сохраняются; проверка выполняется после возможной
  загрузки текстуры и сброса кеша.
- Меняющийся кадр обновляет существующую запись кеша без повторного прохода
  по пересечениям, удаления записи и сдвига списка. Новые/изменившие размер
  области по-прежнему проверяются на пересечение и ограничение памяти.
- С включённой диагностикой строки `[MCGL Phases]` раздельно показывают
  время отрисовки, игрового обновления и анимаций, а также число сэкономленных
  копирований и передач текстур. Это время выполнения вместе с ожиданиями,
  не отдельное время GPU; вложенные интервалы нельзя складывать.
- Текстуры, частота анимаций, количество частиц, дальность, настройки Java/GC
  и исправления fullscreen/сворачивания из 1.4.0 не изменены.

## Изменения 1.4.0

- Галочка «Сохранять логин»: сохраняется только имя пользователя на этом Mac.
  При снятии галочки сохранённый логин сразу удаляется. Пароль не сохраняется.
- Лимит FPS: 60, 120, 144, 165, 180, 240 или «Без ограничения».
  Выбор запоминается и действует со следующего запуска игры. По умолчанию
  дополнительный лимит выключен. VSync и настройки самого клиента могут
  ограничивать FPS сильнее; выбранное значение — верхний предел, а не обещание FPS.
- Ограничитель использует ожидание на игровом потоке без активного кручения
  процессора, не удерживает общий оконный lock и не меняет симуляцию игры.
- Сохранены исправления окон, оптимизации эффектов и настройки памяти из 1.3.0.
- Дополнительно устранены небезопасные вызовы оконного ввода из игрового потока;
  пересоздание fullscreen-окна ожидает окончания перетягивания края окна.
- Освобождение закрытого окна отложено до завершения текущей обработки событий
  AppKit: это устраняет обнаруженное обращение к уже освобождённому окну при
  сочетании растягивания окна и переключения fullscreen.

## Изменения 1.3.0

- Исправлена несогласованная работа OpenGL и AppKit при изменении размера окна:
  обновление поверхности выполняется между кадрами и только при необходимости.
- Старые Cocoa-окна отсоединяются вместе с обработчиками мыши; потеря фокуса
  больше не заставляет клиент пересоздавать fullscreen-окно.
- Размер интерфейса игры обновляется при растягивании окна.
- Удаление частиц из упорядоченного списка больше не сдвигает весь остаток
  массива после каждой исчезнувшей частицы. Количество и порядок не меняются.
- Повторная загрузка идентичного кадра анимированной текстуры пропускается.
  Скорость анимации сохраняется; перекрывающиеся записи и перезагрузка текстур
  сбрасывают кеш (не более 8 МБ на менеджер текстур).
- Новые патчи автоматически применяются к проверенному официальному клиенту.
  Несовместимая структура классов останавливает установку до замены игровых файлов.

Ускорение отдельных операций не гарантирует определённый прирост FPS: результат
зависит от сцены. Дальность, число частиц и качество графики не снижены.

## Требования к системе

- Mac с Apple M1, M2, M3 или M4;
- macOS 14 или новее;
- действующая учётная запись Minecraft Galaxy;
- подключение к интернету на первом запуске.

## Установка

1. Полностью распакуйте ZIP.
2. Перенесите `Minecraft Galaxy ARM64.app` в «Программы».
3. При первом запуске нажмите приложение правой кнопкой мыши и выберите «Открыть».
4. Введите логин и пароль MCGL и нажмите «Запустить».
5. Дождитесь загрузки и проверки официального клиента. Игра откроется автоматически.

При последующих запусках лаунчер проверяет официальный `version.md5/update.lst`,
скачивает только новые, изменённые или отсутствующие файлы, а затем повторно
накладывает ARM64 bytecode/native-компоненты и fullscreen-патч. Пересобирать лаунчер при обычном
обновлении файлов Minecraft Galaxy не требуется.

## Экспериментальная многопоточная оптимизация

Флажок «Многопоточная оптимизация памяти» включает G1GC с параллельной обработкой
ссылок и дедупликацией строк. Часть обслуживания памяти выполняется конкурентно на
других ядрах, что может уменьшить редкие паузы при длительной игре и загрузке мира.
Настройка запоминается и в любой момент может быть выключена для сравнения со
стандартным ParallelGC.

Игровой tick и команды OpenGL остаются на основном потоке: режим не меняет порядок
логики мира и не обещает линейного увеличения FPS.

## Выделенная память

В лаунчере можно выбрать максимальный объём памяти Java: 1024, 2048, 4096,
6144 или 8192 МБ. По умолчанию используются 2048 МБ. Выбор сохраняется между
запусками; native runtime принимает только перечисленные безопасные значения и
возвращается к 2048 МБ при некорректном параметре.

Флажок «Заранее выделять весь выбранный объём памяти» устанавливает начальный
размер Java heap равным выбранному максимуму (`-Xms = -Xmx`). Без флажка Java
начинает с 512 МБ и увеличивает heap по мере необходимости. Эта настройка также
сохраняется между запусками.

Больший лимит не увеличивает FPS сам по себе. Он полезен для тяжёлых наборов
ресурсов и длительной игры, но на Mac с небольшим объёмом оперативной памяти
слишком высокий лимит может привести к давлению на память и swap macOS.

## Диагностика графики без изменения изображения

Флажок «Диагностика графики» включает лёгкие счётчики внутри кастомного LWJGL.
Раз в пять секунд в журнал выводятся FPS, среднее и максимальное время кадра,
время игрового рендера вне `Display.update`, время `Display.update`, ожидание
показа буфера и число пересобранных OpenGL display lists. Разрешение, текстуры,
дальность прорисовки, эффекты и команды рендера этот режим не меняет.

Строки начинаются с `[MCGL Graphics]` и `[MCGL Phases]`. Для обычной игры диагностику можно
выключить в лаунчере; настройка также запоминается.

Игровые данные создаются отдельно в:

`~/Library/Application Support/Minecraft Galaxy ARM64`

Пароль не сохраняется и передаётся игровому процессу через одноразовый локальный
канал.

## Полноэкранный режим

- зелёная кнопка окна переключает нативный полноэкранный режим macOS;
- `Fn + F11` или `Control + F11` переключает его с клавиатуры;
- при выходе восстанавливается последний размер окна (изначально 900 × 700).

## Что находится в архиве

- Cocoa-лаунчер ARM64 и Cocoa-runtime игры;
- минимальная ARM64 Java 8;
- открытые ARM64-сборки LWJGL 2, JInput и OpenAL Soft;
- собственные совместимые библиотеки macOS и установочный bytecode-патч;
- документация и лицензии сторонних компонентов.

Оригинальный клиент и его ресурсы в архив не включены.

## Устранение проблем

Незавершённая загрузка удаляется автоматически. Если уже созданный профиль был
повреждён, полностью закройте игру, переместите папку
`~/Library/Application Support/Minecraft Galaxy ARM64` в Корзину и запустите
приложение снова.

Журнал лаунчера:

`~/Library/Logs/Minecraft Galaxy ARM64/launcher.log`
