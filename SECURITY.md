# Безопасность и приватность

Это неофициальный порт старого клиента, а не аудит безопасности Minecraft Galaxy.

## Учётные данные

Лаунчер может сохранить логин, если включена соответствующая галочка.
Пароль не записывается в UserDefaults и не передаётся аргументом командной
строки: для передачи игровому процессу используется одноразовый локальный FIFO.
Это не исключает нахождения пароля в памяти процесса и не изменяет сетевой
протокол официального клиента.

`native-replacements/src/nixspecific_arm64.c` реализует совместимость со старым
JNI-вызовом авторизации: читает `IOPlatformUUID` Mac и формирует данные из
идентификатора компьютера, логина и пароля. Код использует MD5 и фиксированную
XOR-маску старого формата. **Это не современное защищённое шифрование.**
Не следует воспринимать открытый исходный код как гарантию безопасности
старого протокола или использовать один пароль для разных сервисов.

## Загрузка клиента

В 1.6.6 установщик обращается к зеркалам `f1.mcgl.ru`, `f3.mcgl.ru`, `f2.mcgl.ru`
по HTTP и проверяет файлы по MD5 из полученного списка. Это проверка соответствия
списку, **не криптографическое подтверждение его подлинности**: HTTP и MD5
не защищают от активной подмены списка и файлов. Автоматическое обновление
не следует путать с подписанным каналом доставки.

Проверка версии лаунчера обращается по HTTPS только к GitHub API репозитория
`prilepv/mcgl-arm64`. DMG берётся из соответствующего GitHub Release. Если API
возвращает SHA-256 asset digest, лаунчер проверяет его перед сохранением файла.
Обновление не запускается и не устанавливается скрытно: DMG сохраняется в папку
«Загрузки» и открывается для ручной установки пользователем.

## Подпись приложения

Релиз 1.6.6 подписан ad-hoc и не нотарифицирован Apple. SHA-256 опубликованного
DMG позволяет сравнить файл с релизом, но не заменяет Developer ID,
нотариализацию или независимую проверку исходников и сборки.

## Сообщения о проблемах

Не публикуйте реальные пароли, токены, аппаратные идентификаторы, полный профиль
игры или неотредактированные журналы. Для обычных ошибок используйте Issues.
Не выкладывайте в публичный Issue действующие секреты или подробности
эксплуатации уязвимости до согласования безопасного способа сообщения.
